# Croma written design system candidate

This package implements the actual Croma design system in React and TypeScript. Written specifications take priority. On 4 November the user approved actual same-file component properties, saved styles and original artwork to fill unwritten gaps. Each fallback keeps its actual source and context; a matching style name alone is insufficient. No component has passed full visual acceptance.

The runtime stylesheet is generated partly from [the property registry](evidence/written-values.json). Each entry retains the exact source cell or authored text, surrounding row, table visibility, selector and CSS property. The local archive recovered all 149 inventoried tables. Hidden descendants are excluded. The user approved written tables even when the entire table is hidden; hidden template/descendant rows remain excluded. Root visibility is retained in the evidence.

## Components and contracts

The written-guide Button branch exposes Filled/Outlined/Text × Large/Small × Enabled/Disabled/Hovered, with dark/light source contexts. Icon has a fixed 32px container and 16px icon slot, Enabled/Hovered/Selected states, and requires caller-provided artwork and an accessible name. `Selected` is independent from hover for Icon and Segmented; both expose `aria-pressed`. Large/Small do not apply to Icon or Segmented. Source labels default to “Label”. Optional icons use the shared source-preserving Icon renderer, which can uniformly scale and alpha-mask original monochrome artwork without editing its SVG.

The full `Segmented` collection represents the direct Layout exemplar 245:36918 (Double Text Toggle): the written outer container is 32px with 4px corners; actual inner options retain 28px height, 100px corners and bold 14/20/0 text metrics. The vertical inset is derived from (32−28)/2. Actual horizontal inset is 4px and the 2px gap is derived from source option positions. Its equal columns and arrow/Home/End navigation are responsive interaction mechanics. `Button Type="Segmented"` remains a compatibility **individual option**, not the full collection. Earlier application of outer 32px/4px rules to every inner option was an unaccepted scope error and is superseded.

Filled/Outlined retain written 40/32px heights, 128/112px minimum widths, 24px inline padding and 4px corners. Text uses 8px margins. Labels remain single-line and truncate in narrow layouts. Outlined strokes are painted inside the bounds and do not consume padding, matching the source box model. Source foregrounds are scoped by type, size and state; they are not global palette aliases. The separate local Button set 393:72921 has different native variant names and is being integrated as a distinct branch, without assuming Primary=Filled or Mobile=Small. Button’s whole-component review is in progress; no branch is yet marked fully accepted.

FormField supports native input props and refs, a required indicator, leading images, trailing content, supporting text, error replacement, validation associations and read-only behavior. Written image height is 24dp, implemented as 24 CSS pixels for the web prototype; read-only input opacity is 38%. Compatibility State aliases do not imply verified visual variants.

Checkbox, RadioGroup and ToggleSwitch preserve native input semantics. Checkbox now uses original same-file selected/mixed artwork with the written 4px radius; disabled artwork is separate, with written opacity applied once. This supersedes the historical native-radius gap, but requires a fresh browser and visual review before acceptance. The actual switch track is 52×24; the written 24px height was previously misread as a square width. Its original track artwork is preserved and a 40px minimum target remains. The canonical switch track has no authored label. Caller-supplied visible label text inherits the consumer’s typography and foreground; this is a documented web adaptation, not a source-exact Toggle label style. Radio selected/unselected and disabled appearance now uses original24px source artwork, preserving native radio selection and keyboard behavior.

Choice, Filter, InfoChip, InputChip and Badge implement their written container layouts and role bindings. Ordinary Filter is 32px high; its logo layout is 48px. Badge is the separately documented 28px chip with a 16px bottom-right corner. ChipGroup wraps inline with a 12px gap. Interactive chip targets extend transparently to the documented minimum 48px without enlarging their visible containers. Long chip labels truncate.

Accordion supports native disclosure behavior, controlled open state, a caller-provided icon, 16px padding, a 1px divider, 16px icon/heading gap, 8px content gap and expanded 4% state layer. Tabs supports disabled items, fallback selection, arrow/Home/End navigation, equal segments, 48px height, a 2px indicator and 8px inline padding. Dropdown retains native selection and stays within narrow containers.

PopUp, BottomSheet and NavigationDrawer use modal dialog semantics, focus return, explicit Tab containment, Escape and close callbacks. NavigationDrawer closes on item selection and scrim interaction. BottomSheet adds a keyboard-accessible dismiss handle and a downward drag gesture. Drag thresholds are interaction mechanics rather than source design measurements. PopUp supports leading dismiss and trailing confirm action slots, respecting document direction. Drawer and Menu implement written profile, NeuPass, quick-link, section, row, submenu, message and divider layouts. Supplied close-icon artwork can occupy the documented 24px slot.

Tooltip supports focus, persistent hover, Escape dismissal and viewport clamping/flipping. Its actual written layout supplies 8px padding, 4px radius/gaps, a 16px leading icon and a 32×8px beak slot. The beak and leading information icon now use original same-file exports from the actual guide figures, with native dimensions preserved. This saved-art fallback is distinct from the written slot dimensions. Copied input-field and filled-button tables are excluded from tooltip styling.

SearchBar supports controlled entry, submission, clearing, optional leading and clear icons, and the written 40px container, 16px margins, 12×8px padding and 4px radius. Steppers supports horizontal/vertical layouts, string or structured steps, optional icons/descriptions, completed/active/inactive role bindings and the written path dimensions. Label supports text badges, number indicators and dots, explicit sizes/shapes/colours/emphasis and a 16px icon slot. Text badges default to the written Large 32px size and All rounded 4px shape; dots use the explicitly documented circular shape. DividerLine supports the written thickness variants and optional centered text with an 8px gap. Card supports written aspect-ratio names and surface/state role bindings. Card composition names such as Grid, Carousel and With Copy remain documented composition patterns, rather than invented visual variants.

Header, Chat and StickyFooter provide responsive composition and appropriate native regions. Their embedded search specifications do not establish geometry for the entire header, chat or footer.

## Unresolved values and acceptance

Written specifications do not numerically define every semantic role. Approved saved-property bindings now fill reviewed contexts; remaining unbound roles stay explicit. The saved registry records source nodes, exact override paths and style key/version references. Shared names are not treated as proof that components use the same value. The user-supplied Switzer Variable font is loaded through `@croma/figma-foundations/fonts.css` and the shared `--croma-font-family` setting. Source typography metrics are unchanged.

The property registry distinguishes known role associations from missing numeric definitions. Source transcription, source applicability, browser geometry, behavior and full visual acceptance are separate checks. Written fixed heights are implemented as minimum heights where content must grow; this policy supports long content but does not establish exact final height without the unresolved typography metrics.

The earlier MCP quota errors and rejected guesses remain historical evidence. Same-file saved properties are now eligible runtime sources only where reviewed under the 4 November policy. Local archive recovery superseded the retrieval gaps. [Acceptance gaps](evidence/acceptance-gaps.json) and [component status](evidence/component-completeness.json) retain the current limitations.

## Build and checks

Prototype extensions 0.5.0 include `PlainSection`, `SurfaceCard` and `HelpDisclosure`, plus shared field/choice/focus/contrast/action rules. See `docs/FIGMA-DESIGN-HYGIENE.md` in the source release and Storybook → Prototype extensions → Design hygiene. These are user-approved composition contracts, separate from authored Figma variants. Run the extension regression suite with `npm run figma:test:extensions` after building Storybook.

Consumers import `@croma/figma-ds`, `@croma/figma-foundations/fonts.css` and `@croma/figma-ds/styles.css` from the built packages. The package exports JavaScript, declarations and styles. Raw archive data is excluded from distribution.

Build: `node packages/figma-ds/scripts/build.mjs`.

Written provenance check: `node packages/figma-ds/scripts/verify.mjs`. Numeric comparisons use token boundaries, so 8px does not match 28px. Source row context is preserved; matching a literal does not by itself prove correct element or state scope.

The focused Chromium review checks controlled mixed-checkbox state, switch selection, controlled disclosure, disabled tab navigation, modal Escape/close/unmount callbacks and focus return, forwarded input refs, validation associations and selected computed geometry. Broader independent Storybook acceptance records are maintained in the application folder. Those observed results remain separate from source transcription checks.

The historical 3 November 279-rule independent browser checkpoint inspected 535 unique properties: 223 numeric properties verified, one measured unaccepted checkbox-radius gap and 311 properties blocked by unresolved semantic definitions. No numeric properties were left unmeasured. It also passed 214 foundation checks, 26 interaction checks and six layout checks, with no console or citation errors. These checks establish their recorded scope; they do not certify every component as visually complete.

The 3 November written-only reconciliation found no additional concrete independent code work within its then-audited requirements. The 4 November fallback policy reopened component work and Button is the active first acceptance gate. This does not resolve the missing numeric semantic definitions, required artwork, unverified annotation scope or the measured native-checkbox radius gap. Final browser results include a stable fingerprint of the actual code, styles, fixture and production build.

## Added actual source branches

- `LocalAccordion` maps the separate `Accordion` set463:83388. `Background="Light"|"Dark"`, `Title="On"|"Off"` and `State="Close"|"Open"` retain its exact source values. Supply `State` with `onStateChange` for controlled use; use `defaultState` for native interactive disclosure. `sectionTitle` is editable content and is displayed only for Title On. The guide `Accordion` remains a separate component.
- `ColourAccordion` maps “Accordion - Colour”468:82805. Each item supplies editable heading/content, one of the original Sparkle/Delivery/Deal/Store source slots and optional `defaultOpen`. Original source artwork and source radial fills are bundled; no full-component screenshot is used.
- `Card Branch="Local" Theme="dark"|"light"` maps the six actual Elevated/Filled/Outlined masters171:38467–69 and171:38474–76. The existing `Branch="Guide"` remains the default. Theme and Branch are explicit code mappings for the two source surface families; they are not claimed to be authored Figma variant property names. For a whole-card native action, use `href` or `onActivate` plus a title or `actionLabel`; secondary controls remain siblings of the primary action. Do not attach a second whole-card activation handler to the outer section.
- `CardSkeleton` maps the loading widget171:18917 in the page's Skeleton Card example. It has the source's dark360×360 appearance and no invented animation or light variant.
- `FormDropdown` maps the six tuples in `form Dropdown`840:82414. It preserves State/Visible spellings and shows the source floating label in selected/filled states. `Dropdown` continues to map `Default Dropdown`1715:79529; its hidden floating captions remain hidden. State/Visible forcing is intended for source-state previews; omit them for interaction driven by the selected value.

Native uncontrolled Toggle and Checkbox state metadata synchronise with native form reset. Controlled state remains the consumer's responsibility. Drag sheets follow handle movement, restore after cancelled/short drags and dismiss after a sufficient downward drag. These functional mechanics do not claim extra visual source variants or source-authored animation physics.
