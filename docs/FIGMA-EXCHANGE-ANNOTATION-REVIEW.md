# Exchange prototype annotation review

5 November 2026. Review of the user's 17 UI annotations on `http://127.0.0.1:8774/`, serving `experiments/final-exchange`. The reviewed baseline was pinned to DS0.3.0; the corrections use the working0.4.0 library. The supplied screenshots establish the annotated appearance; source inspection below establishes implementation causes. The integrated consumer has been rebuilt and checked; exact verification scopes are recorded below.

The main finding is an integration problem: the prototype combines a legacy HTML/CSS journey with React DS islands and a broad dark-theme override layer. Applying the DS did not remove the old layout and state rules. Several issues therefore come from the adapter and consumer composition, rather than defects in the original Figma components. A smaller set needs reusable extension contracts so the next prototype does not repeat the same local fixes.

## Inspected evidence

- Prototype `README.md` and `migration-manifest.json`: selected original HTML journey, DS 0.3.0 pin and explicit migration limits. Its native catalogue search, choice grids, imagery and progress retain original interactions; they are not all replaced by shared React components.
- Prototype `src/skin.jsx`: `island()` puts `ds-button` on its span host; `decorate()` also puts that class on the native `PrototypeButton`. The adapter maps `.bag-tertiary` to `appearance="quiet"` and instantiates a generic `CommerceHeader` without search or location props.
- Prototype `src/skin.css`: `.ds-button` forces inline-flex, padding, minimum height and gaps on every matching element. The same rule therefore gives geometry to both wrapper and button. Broad `!important` colour/fill rules also override individual legacy layout decisions.
- Prototype `index.html`: legacy selected-pill border/weight changes, card padding/type rules, result storage badge, standalone result label, heading spacing, responsive action-grid rules and question section dividers.
- DS `packages/figma-ds/src/PrototypePatterns.tsx` and `prototype-patterns.css`: `PrototypeButton` itself renders one native button and supports primary/secondary/quiet; the default shared component does not add the second wrapper padding. `ActionGroup`, `CompositionDialog` and `InlineFieldAction` already supply extension patterns, but the legacy flow does not consistently use them.
- DS `CommerceHeader.tsx`: an explicitly labelled editable prototype extension, not a verified reconstruction of Croma's current live website header. The root agent separately inspected the live header for this request.

## Reusable contracts

These are user-approved extension requirements from this review, not recovered Figma specifications.

1. **Selection geometry and state:** selected and unselected states keep border width, font weight, padding, minimum height and icon slot sizes constant. Use the theme's primary green for selected stroke and text; use a neutral grey selected surface and transparent unselected surface. Disabled and focus treatments remain visible and independent of selection. Apply one policy to both compact and illustrated layouts.
2. **Neutral integration boundary:** a React island host is a structural mount point only. Put component classes, padding, typography, minimum size and appearance on the actual shared component. Do not reuse one visual class on host and child. Attribute/event mapping must preserve native IDs, names, disabled state and delegated actions.
3. **Action intent and grouping:** primary, secondary and quiet are explicit intent, not inferred forever from legacy CSS class names. Purchase actions use primary plus secondary side by side where space permits. Flow actions use a leading Back group and trailing Save/Continue group, with a documented narrow transformation.
4. **One inset owner:** surface content, summary and footer share one inline inset. Child layout rows and mount hosts do not add another inset. Outer section spacing, inner surface padding and control padding are separate responsibilities.
5. **Search result anatomy:** a result surface owns an optional heading/count, option list, empty/loading/error feedback and its trailing metadata column. Heading/status rows are not options. Announce actual match count; a disabled or presentation row must not become a selectable phone. Preserve keyboard active/selected IDs when results change.
6. **Text-paired icon:** transparent icon slot, inherited foreground, explicit size and optical centring. A background tile is a separate named composition, not an accidental dark-theme rule.
7. **Scoped header preset:** a current-live-site header is its own dated, configurable preset with route/search/location/actions supplied by the prototype. Generic CommerceHeader remains useful; it does not automatically become an exact live-site reproduction.
